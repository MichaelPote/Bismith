# FR8.20 — Project previews

**Status:** done

## Goal

The new-project wizard (FR8.16) rendered every card to show it: each card's generator shaders compile first (0.5–7 s
each cold on D3D11), then a short render. A project file can now carry a small picture of itself, and a card whose
project has one shows it at once.

## Design

- **Format**: `Project.preview` — optional, last in the file. A data URL of the final (post-processed) image: WebP
  with its alpha (JPEG over the viewport's alpha checkerboard where the browser can't encode WebP; cards and menus
  show previews over that checkerboard too, `--alpha-bg`), the longest side scaled (smoothly) to at most 256 px — smaller textures
  keep their size — at quality 0.8 (`PROJECT_PREVIEW`): sharp on a wizard card (150 px and up, 2× screens too). A
  64 px texture is a few KB, a 256 px one 10–35 KB of base64. Preset tiles in the menus (~76 px) keep 128 px at
  quality 0.6 (`TILE_PREVIEW`), a few KB each. On load it is kept only
  when it is a base64 WebP / JPEG / PNG data URL of at most 256 KB (`isPreview` in `core/serialize.ts`); rendering
  ignores it.
- **Writing**: Save project (Ctrl+S) and Export all maps capture it from what the viewport shows at that moment
  (`capturePreview` in `render/preview.ts`, the export's final pixels). Only the file gets it — the open project is left
  alone, so saving adds no undo step; if nothing has rendered yet the previous preview is kept.
- **Wizard**: every card shows its preset's preview as an image; since FR8.16a the wizard never compiles or renders
  (a preset without one shows a placeholder).
- **Examples**: the presets are files in `public/presets/` (FR5.4 v2), so each carries its own preview: `tools/previews.ts`
  renders them on the GPU harness and writes the preview into the file (`--missing` for new ones).
  `presets.test.ts` checks every preset has one — after adding or changing a preset, run `npx tsx tools/previews.ts`
  (`--only project/bricks,torch` for some).
