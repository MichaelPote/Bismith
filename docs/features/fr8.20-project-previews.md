# FR8.20 — Project previews

**Status:** done

## Goal

The new-project wizard (FR8.16) rendered every card to show it: each card's generator shaders compile first (0.5–7 s
each cold on D3D11), then a short render. A project file can now carry a small picture of itself, and a card whose
project has one shows it at once.

## Design

- **Format**: `Project.preview` — optional, last in the file. A data URL of the final (post-processed) image: WebP
  (JPEG where the browser can't encode WebP), the longest side scaled (smoothly) to at most 128 px — smaller textures
  keep their size — at quality 0.6. A 64 px texture is ~1–2 KB, a 128 px one 2–6 KB of base64. On load it is kept only
  when it is a base64 WebP / JPEG / PNG data URL of at most 256 KB (`isPreview` in `core/serialize.ts`); rendering
  ignores it.
- **Writing**: Save project (Ctrl+S) and Export all maps capture it from what the viewport shows at that moment
  (`capturePreview` in `render/preview.ts`, the export's final pixels). Only the file gets it — the open project is left
  alone, so saving adds no undo step; if nothing has rendered yet the previous preview is kept.
- **Wizard**: a card whose project has a preview decodes it once (`decodePreview`) and is left out of the shader batch
  and the render queue; a preview that fails to decode drops out and the card renders as before. The suggestions take
  fresh random colours each time, so they still render.
- **Examples**: the presets are built in code, so `tools/previews.ts` renders each on the GPU harness and writes
  `src/presets/previews.ts` (preset id → preview, ~25 KB for the 11); `PRESETS` attach them to the projects they build.
  `presets.test.ts` checks every preset has one — after adding or changing a preset, run `npx tsx tools/previews.ts`
  (`--only id1,id2` for some).

## Checklist

- [x] `Project.preview`, validated on load, last in the file
- [x] Written on save and in the maps + project export (no undo step)
- [x] Wizard shows previews without compiling or rendering; falls back to rendering
