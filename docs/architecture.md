# Bismith — Architecture

Bismith is a browser-based procedural **flat-surface texture generator**. It is meant to be equally at home
making Quake-1-style pixel-art wall/floor textures and skeuomorphic UI surfaces (buttons, wells, panels, bezels).

This document records the guiding ideal and the architecture that implements it. The per-feature plans and
progress checklists live in [`docs/features/`](features/) — see the [feature index](#feature-index).

---

## 1. The ideal (project brief)

These are the founding requirements. Everything below exists to serve them.

1. **Layers.** The final output is composed of a stack of procedural operations ("layers"), each with its own settings.
2. **Material channels.** The working project tracks:
   - **Diffuse** — surface colour, no lighting (plus an alpha/opacity for UI cut-outs).
   - **Height** — which areas are raised or sunken.
   - **Roughness** — shiny vs matte.
   - **Normal** — surface direction. _Always derived from Height, never edited directly._
   - **Emissive** — areas that emit their own light.
3. **Global lighting** is a project setting: a sky light, individually placed lights, ambient strength, etc.
4. **Rendering** is path traced. Three.js provides the WebGL2 plumbing; the path tracer is our own fragment shader
   specialised for flat (height-field) surfaces, with shapes expressed as SDF primitives and SDF operators.
5. **Post-processing** runs on the HDR render: glow for bright areas, 8-bit palettisation for the retro look, etc.
6. **Reference matching.** Given example textures, iterate toward a resemblance — either by an automated
   (evolutionary / reinforcement-style) optimiser, or by Claude using a render-and-compare harness, or both.
7. **Procedural layers needed:** noise of all kinds; lines, curves, boxes, rectangles, circles; bricks, Voronoi,
   clouds; convolution filters that act on the layers below (blur, bevel, etch…).
8. **Post filters needed:** glow, blur, 8-bit, tonemap.
9. **UI** follows the _Cinderforge_ design system (tokens in `src/styles/tokens.css`).
10. **Platform:** browser app, Vue 3 + Vite.

### Design principles derived from the brief

- **Pixels are first-class.** Material maps are evaluated at the output resolution, one texel per pixel, so pixel
  art stays crisp. Sizes that matter to pixel artists (bevel width, mortar, line thickness, blur radius) are in px.
- **Tileable by default.** Noise frequencies snap to integers, shapes/filters wrap, and rays wrap around the
  torus, so a wall texture repeats seamlessly. UI projects turn tiling off.
- **Everything is a uniform.** Moving a slider never recompiles a shader; it only updates uniforms and re-runs the
  (cheap) layer passes. Shaders compile once per layer _type_.
- **HDR until the last moment.** Material, lighting and render buffers are float; tonemapping and palettisation
  are explicit post filters, so glow can key off real over-bright energy.
- **Relief is fine by default.** Real texture relief is shallow: a bevel should rise ~1 px over a 2–4 px run,
  so shading (not long cast shadows) carries the shape. The default `heightDepth` is 2 px per 1.0 of height and
  shape/pattern layers default to a height amount of 0.4–0.5, i.e. about a 1 px rise.
- **Projects are plain JSON.** A project fully describes a texture, so it can be saved, diffed, generated by an
  optimiser, or written by hand (by a person or by Claude through the harness).

The **Engine** (`src/render/engine.ts`) owns the WebGL renderer and orchestrates the stages. It watches the
project for changes and invalidates the minimum work: a layer edit re-runs stages 1–4, a light edit restarts
accumulation (3–4), a post edit re-runs only stage 4, a view change only stage 5.

## 4. Coordinate conventions

- **Pixel space.** Shaders work in GL pixel space: `p = gl_FragCoord.xy`, origin bottom-left, y up, pixel centres
  at `.5`. Texture size is `uRes = (W, H)`.
- **User space.** The UI and project JSON use image conventions: positions are fractions `0..1` with **y down**
  (0,0 = top-left). Uniform upload converts (`y_gl = 1 − y_user`). Angles are degrees, clockwise on screen.
- **Units.** Lengths (bevel, thickness, radius, mortar, blur) are **px**. Noise/pattern scales are
  **cells across the texture** (rounded to integers per axis when tiling). Height is unitless; `1.0` of height is
  `project.heightDepth` px tall in world space.
- **World space (path tracer).** `x, y` in px (GL orientation), `z` up in px. A light's azimuth is measured
  clockwise from the top of the image; elevation from the surface plane.
- **Normal maps** are exported in OpenGL (Y+) convention by default, DirectX (Y−) optional.

## 5. Data model (`src/core/project.ts`)

```ts
Project {
  version, name,
  width, height,            // output resolution, px (non-square allowed, e.g. 256×64 buttons)
  tileable,                 // wrap everything on a torus
  heightDepth,              // px of world height per 1.0 of height (default 2 — keep relief fine)
  seed,                     // global seed mixed into every layer seed
  base: { color, roughness, specular, height, opacity },
  layers: Layer[],          // the stack in evaluation order (first = earliest); relief = a layer with Diffuse off
  groups?: LayerGroup[],    // named blocks of layers (members, limit, shown), each contiguous (FR8.3)
  lighting: Lighting,
  render: RenderSettings,
  post: PostFilter[],       // applied in order
  preview?: string,         // small WebP / JPEG data URL of the final image, written on save (FR8.20)
  variants?: VariantSet,    // FR10: the same stack with each variant's own settings (core/variants.ts); in memory
                            // the project is the active variant, in a file the base, with the others' changes
}

Layer {
  id, type, name, enabled, locked?,     // locked = optimiser must not touch it
  params: Record<string, ParamValue>,   // flat: the type's own params + the common generator params
}
```

Generator layers carry the common params (bevel, shaping, mask — Write to, Limit to — and one group per channel
output) flat in `params`, next to the type's own params, with prefixes (`sdf_*`, `sh_*`, `m_*`, `dif_*`, `op_*`,
`h_*`, `r_*`, `s_*`, `e_*`; see `src/layers/commonParams.ts`). Keeping everything in one `ParamDef`-described record
means the properties panel, the uniform upload and the optimiser all treat outputs exactly like any other
setting — e.g. the optimiser can tune a colour ramp or a height amount.

### 5.1 Layer types and the registry (`src/layers/`)

Every layer type is a `LayerDef` registered in `src/layers/registry.ts`:

```ts
LayerDef {
  type, label, category: 'noise' | 'shape' | 'pattern' | 'filter' | 'adjust',
  kind: 'generator' | 'filter',
  params: ParamDef[],            // drives both the UI and the uniforms
  glsl?: string,                 // generator: defines `GenOut gen(vec2 p)`
  sdf?: boolean | 'mask',        // generator produces a signed distance (shapes, bricks, voronoi); 'mask': for the
                                 //   mask it writes only, the generator shapes its own value and coverage (Blisters,
                                 //   Splats, Scratches, Cable, Hammered, Caustics) — the Edge card still applies: Bevel (0 by
                                 //   default) × its own value, Anti-alias read by the generator itself (u_aa)
  maskWrite?: (params) => 'shape' | 'coverage' | false, // what it writes into its mask (masks.ts, FR8.23)
  maskSources?: MaskSourceDef[], // what it can write into a mask (Write to › Source): parts, selections; its Output
                                 //   enum's options are added by the registry (FR8.23)
  parts?: string,                // its own level per part (gGenLevel: roughness, specular, metalness, emissive) —
                                 //   Roughness / Specular / Metalness / Emissive offer Source › Parts (Greebles)
  readsMask?: boolean,           // reads maskIn() in its shader (Chips, Tabs, Glass)
  maskSource?: (params) => string | null, // the mask it reads as its source (edge filters, Mask area)
  prepare?: (ctx, layer) => textures, // generator or filterGlsl filter: GPU pre-passes over the current state
                                 //   (jump-flood field, blur) whose `textures` the shader reads as t_<name>
  derivedUniforms?: { decl, compute(params, canvas) }, // per-render CPU values as d_<name> uniforms (lattices,
                                 //   gcds, fits) — uniform-only work that would otherwise run per pixel
  linkedDefaults?: (params) => params, // defaults that follow other params (Drips: Height on for Sources); a value
                                 //   still at its old default moves with them, one set by hand stays
  run?: (ctx, layer) => void,    // filter: custom multi-pass implementation (Blur); limited, it pays a snapshot + blend
  defaults?: Partial<LayerOutputs>
}
ParamDef { key, label, type: float|int|bool|color|enum|seed|gradient|curve|text, default, min, max, softMin, softMax,
           step, unit, options, group, showIf, optimize, hint, mask }   // mask: 'read' | 'write' — a mask-name field
```

`ParamDef`s are the single source of truth: the properties panel renders controls from them, the material
pipeline uploads them as uniforms named `u_<key>` (enum → option index, colour → linear `vec3`, gradient →
`vec4 u_<key>_stops[8]` in sRGB + `u_<key>_count`, text → not uploaded unless it declares a `bitmap` encoding:
`pixels` / `font` → packed cells `ivec4 u_<key>[64]`, `points` → polygon vertices `vec4 u_<key>[64]`, both with an
`ivec2 u_<key>_size`), and the optimiser reads the ranges to know what it may mutate.

### 5.2 Generators

A generator's GLSL returns `GenOut { float value; float mask; float rnd; float sdf; … }`:

- `value` — the pattern value `0..1` (noise value, or a bevel profile for SDF shapes).
- `mask` — coverage `0..1` (anti-aliased inside-ness for shapes; `1` for noise).
- `rnd` — a per-feature random `0..1` (per brick / per cell / per repeated shape instance) for variation.
- `sdf` — signed distance in px, negative inside (SDF generators only).
- `height` — optional (`genOutHeight`): a signed height profile of the generator's own. Height › Pattern adds it
  (× amount) instead of the value, wherever it is non-zero — not limited by the coverage, so it can rise past what the
  other outputs paint and sink below the surface (Blisters: a lifted lip outside the hole, the hole below).
- `own` — how an SDF generator's value relates to its shape: 0 the wrapper draws the shape (value = bevel profile,
  coverage = inside); 1 (`genOutOwn`) the generator painted its own value and coverage and `sdf` only goes to the mask
  it writes (Cracks' carve); 2 (`genOutShaded`) the generator's pattern × the bevel of the combined shape, its
  own coverage (Wood's grain on its planks).
- `fid` — the feature's own random, which the mask it writes records (FR8.23): `rnd` may be tinted for colour and
  `feat` zeroed where a generator varies heights itself. `genOut*` set it from `rnd`; `genOutSmooth` −1 (no features).
- `bdist` — optional: the distance the bevel is measured in with Bevel aspect applied (px of Bevel, negative inside).
  It is the plain distance in the space the aspect stretches, so bevels of different widths meet in a clean mitre.
  Without it, the aspect comes from the direction of the shape's distance gradient, which steps on every mitre. Every
  SDF generator with corners computes it with GLSL_BEVEL's toolkit (`commonParams.ts`): `bevelFrame`, `bevelLine`,
  `bevelSeg2`, `bevelArc2`, `bevelEllipse`. It does so only under `bevelAspectOn()`, which is true only in the shader
  variant compiled for a layer whose aspect isn't 1 (`#define BEVEL_ASPECT`, `shaderKey` in `materialPipeline.ts`;
  the editor compiles that variant in the background). The usual shader carries none of that code.
- `hval` — optional: a separate 0..1 value for Height › Pattern, shaped like the value (Wood: shallower grain in Height
  than in colour). Negative = use the value.

Beside GenOut, a generator may set three globals for Diffuse: `gGenRgb`, a colour of its own in place of the ramp
(Stamp's image); `gGenAlt`, a second value and its weight that the ramp's colour blends toward (shaped like the value) —
where two features of different ramp positions meet within a pixel, their two colours mix instead of the ramp passing
through the colours between them (Bismuth's crystal walls); and `gGenShade`, a brightness the colour is multiplied by,
its own shading kept out of the value so the ramp still picks the hue (Bismuth's deeper treads), with `gGenGrey`, how
far the colour goes grey toward its own luminance (its quieter recesses). `gGenTransmit` is the share of the colour it
lays that is transmitted light (Ice's clear ice): seen through, not shaded by the surface, so it goes to Emissive instead
of the albedo (`layTransparent`).

Transparent media share one GLSL helper, `GLSL_TRANSPARENCY` (`src/layers/glsl/transparency.ts`, in every material
shader): the normal of a slope, the lens shift through it, the layers below seen through (`seenThrough` samples
`tAlbedo`), tinting, grazing-angle rims, the inner glint where a dome focuses light, and `layTransparent`, which splits a
colour into lit albedo and transmitted light. The Glass filter and Ice both go through it; new refracting layers should
too. Likewise, layers that hang things from the relief below share `src/layers/ledges.ts`: the ledge test (`LEDGE_GLSL`,
`ledgeParams`) and the pass that finds each cell's strongest ledge pixel (`ledgeCells`) — Drips' trails, Blisters'
blisters and Ice's icicles.

The common generator wrapper then:

1. **Mask write.** A layer writes one **mask** by name (Mask › _Write to_, `mk_target`; shape layers default to the
   _Shape_ mask, see 5.4). A shape layer combines its distance with what the mask held by its Mode (`mk_op`: `normal |
   union | subtract | intersect | smooth union | smooth subtract | smooth intersect`); coverage and bevel profile are
   computed from the _combined_ distance, so a rect unioned with a circle bevels as one shape. Other layers write
   their coverage. Masks follow the stack: only the layers after a writer see what it wrote.
2. **Profile.** For SDF generators `value = profile(insideDistance / bevelWidth)` with profiles
   `flat | linear | smooth | round | cove | ridge | steps | custom` — _custom_ is an editable curve
   (`bevel_curve`: up to 8 points that may rise and fall — rims, dishes; Fritsch–Carlson tangents, so it never
   overshoots between points), e.g. a steep 1–2 px edge followed
   by a long, gentle rise. Flat profiles (or zero bevel) output `1` and leave
   anti-aliasing to the coverage, so edges ramp symmetrically across the boundary. Periodic patterns place
   their edges on pixel boundaries so 1 px features stay crisp with anti-aliasing off.
   **Mask-only generators** (`sdf: 'mask'`) keep their own value and coverage, and the same Edge card shapes them:
   Bevel (0 by default there) × that value — and its Height value, and its own signed height inside the shape, a lip
   outside left alone — by the profile of its distance (`GenOut.bdist` in plain px when given: Scratches' bevel follows
   the faint ones its mask leaves out). In every compile of the type, not a variant: one compiling as the Bevel slider
   leaves 0 would stall the drag.
   Anti-alias is read by the generator (`u_aa`); one that covers everything hides it (Hammered), Caustics the whole
   card.
   **Soft edge** (`soft_edge`, px, both kinds) fades the layer's coverage in from its drawn outline (d = 0.5) to full that
   far inside (`softEdge()` in GLSL_BEVEL), so every channel blends into what is under it; the mask it writes keeps the
   plain distance. **Dilate** (`dilate`, px) grows the shape: `dilateShape()` shifts `GenOut.sdf` and `bdist` before
   anything reads them (so the bevel, Soft edge and the mask it writes all follow) and widens the coverage to the new
   outline; a mask-only generator's own value is what it gives out there (Splats: thin liquid).
3. **Shaping.** `domain warp` (the sample position is displaced by smooth noise before `gen()` — the whole pattern
   warps coherently), `invert`, input levels (`lo..hi`), `gamma`, `posterize steps`, and a `cutoff` that keeps coverage
   only where the shaped value reaches it (sparse flecks from white noise, islands from fBm). The Value section
   draws a graph of all this (`ShapingGraph.vue`, maths in `src/layers/shapingPreview.ts`, a CPU mirror of the
   GLSL): a cross-section through one feature — outside, the bevel's rise, full, the fall, outside (a plain
   0 → 1 → 0 sweep on layers without a shape) — with the dashed unshaped value behind it. With Height on, Height ›
   Amount and Offset are mirrored under the graph (the same params), so the curve's strength is set beside it.
4. **Limit.** Multiply coverage by its _Limit to_ — up to four masks by name with ∪ ∩ −, and Invert (`lim_*`),
   intersected with its material's limit — and/or a soft height range of the current surface (`above | below level`).
   This is how dirt collects only in crevices.
5. **Channel outputs.** Each enabled output maps the value into a channel and blends it in, weighted by
   `mask × opacity`:

| Output    | Source                        | Mapping                                     | Modes                                                                         |
| --------- | ----------------------------- | ------------------------------------------- | ----------------------------------------------------------------------------- |
| Diffuse   | value / flat / random / shape | gradient ramp (≤8 stops) + colour variation | normal, multiply, screen, overlay, add, subtract, darken, lighten, soft light |
| Opacity   | coverage                      | —                                           | replace, multiply, union (max), subtract                                      |
| Height    | value / flat / random / shape | `value × amount + offset`                   | add, subtract, max, min, replace, multiply                                    |
| Roughness | value / flat / random / shape | `mix(a, b, value)`                          | replace, multiply, add, min, max                                              |
| Emissive  | value / flat / random / shape | `colour × intensity × value` (HDR)          | add, replace, max                                                             |
| Specular  | value / flat / random / shape | `mix(a, b, value)` level 0..1               | replace, multiply, add, min, max                                              |

_Shape_ is inside the layer's own shape (1 in, 0 out, anti-aliased; 1 for layers without a shape) — the shape without
its pattern, for layers that paint their own value over it (Wood: rougher gaps than boards, the grain ignored).

Height also has a **per-feature variation**: each brick / cell / instance scales the amount by its own random share.

Diffuse blending is done in sRGB space (like a paint program); results are stored linear.

Beyond the procedural families, three generators take hand-authored input (FR7.5): **Stamp** (a pixel bitmap typed
as rows of characters — insignia, emblems), **Label** (pixel-font lettering) and **Path** (polygons from a vertex
list — chamfered cut-outs, channels, inlays), all as SDFs so bevels and masks apply; and **Cable**
draws tubes wound on a helix (coils, twisted rope mouldings). **Drips** (FR7.7) runs stains down from scattered
sources and ledges, and **Blisters** tears ragged holes of peeling paint at the same sources (both placed through
`src/layers/dripSources.ts`, so the same seed lines them up); **Hammered** lays dish dents on concentric rings around a few centres
whose regions interlock along arcs. **Cracks** (FR8.17; was Chips & splits, listed with the filters) damages whatever is in its mask (the Shape mask):
breaks, flake scars struck in from the edges, cracks and faults. (Wood's splits are the **Splits** filter's, FR8.29: it
pulls the layers below apart along the dark lines of their colour — a ring's latewood — into tapering, bevelled
splits that push the material aside.) **Rock**
(FR8.18) builds natural rock faces from blocks in strata on a sheared lattice — each block a mesa with its own height,
tilt and draped scarps, finer facets, joints, folds — with outputs for the relief and for paint (scarps, crevices, rain
streaks). **Grass** (FR8.21) strews tapered blades that bend, curl and waver, in depth over one another, shaded light at
the tips and dark among the roots, with tufts, bare patches and two kinds of blade on one ramp. **Stone blocks**
(FR8.22) lays a wall of rock-faced ashlar — courses of varying height, blocks split into slabs and short pieces, some
running through two courses — each face pitched with flake scars struck in from its edges, with outputs for the
relief and for paint (joints, scars, open gaps). **Mask area** (FR8.23) only selects: from the surface so far
(crevices, high spots, slopes, slopes facing a direction, a height range) or from a mask's features (inside each one
with its own random, a gradient across each, a band at one side), with noise Breakup — to write a mask or paint. **Liquid
splats** (FR8.24) throws blood, water or oil — torn cores, jets, droplets and mist, or poured pools — lying flat or
running down in runs that end in a bead, its value the liquid's thickness (a flat top over a rounded meniscus). **Bismuth**
(FR8.25) grows hopper crystals — square faces, or the three faces of isometric cube corners, each grown on the CPU by
rules as a path whose facets step down in spirals, hooks and dead ends — shingled in depth order with daughter crystals
on their corners, as stepped pyramids, coloured by an iridescent oxide ramp in solid facets shaded by depth.
**Crystal** (FR8.26) raises Voronoi cells into pyramids of flat faces from each edge to the tip, in up to four layers
combined by max (finer crystals growing out of the valleys), each facet its own shade, with lit ridges, glints and a
star of refracted wedges seen through it — cut glass, gem clusters, loose stones. **Ice** (FR8.28) lays a sheet of ice
over the layers below — what is under it refracted through its rippled surface, coloured by its depth along a ramp with
subsurface scattering — with glinting surface bumps, cracks going down into it at an angle (a hairline and a veil to one
side), long and star cracks, bubbles and stacks of them, specks, blades of frost, and icicles hanging from the overhangs
in the relief below.

**Generator GLSL must compile fast on D3D11.** On Windows, Chrome and Firefox run WebGL through ANGLE on D3D11,
whose shader compiler inlines every function call and unrolls every loop with a constant count. A per-pixel search
over neighbouring cells that calls helpers which search their own neighbours multiplies into thousands of inlined
copies, and the compile takes minutes and hangs the browser (OpenGL and SwiftShader compile the same shader
instantly, so it only shows on Windows). Keep the per-pixel work flat: precompute anything per node or per cell on
the CPU (`cpuData` → a data texture, as Traces & mazes and Cable do), and give unavoidable loops a uniform-derived
count. Check a new heavy generator on D3D11 with the GPU harness (`--backend windows`, FR7.1). Even a reasonable
generator takes a moment to compile on first use, so the add-layer / add-material actions precompile any generator
shader not used yet this session behind a busy modal (`withShaders` in `ui/actions.ts`, `Engine.precompile`): off the
main thread where the browser has `KHR_parallel_shader_compile`, otherwise with the modal up before the page stalls.

### 5.3 Filters

Filters read the current channels and rewrite them in one `filterGlsl` pass (`applyFilter`), which also applies
their limit, after optional `prepare` pre-passes: bevel and etch (jump-flood distance field, or a mask's exact
distance), cavity / edge wear (curvature = height − blur(height)), height-from-diffuse (blurred luminance), splits
(the weak lines of the colour or height below, the grain's streamlines and what runs along them: FR8.29); warp, glass,
levels, HSV and symmetry need none. Only Blur (separable Gaussian) owns a multi-pass `run()`.

### 5.4 Channel storage (GPU)

The material state is three RGBA float textures, written together via MRT and ping-ponged per layer, plus a fourth
output for the mask a layer writes:

| Attachment | R          | G              | B            | A                  |
| ---------- | ---------- | -------------- | ------------ | ------------------ |
| `albedo`   | diffuse r  | diffuse g      | diffuse b    | opacity            |
| `surface`  | height     | roughness      | metalness*   | (unused)           |
| `emissive` | emissive r | emissive g     | emissive b   | **specular level** |
| `mask out` | distance   | feature random | feature flag | —                  |

\* Metalness starts at the base material's Metalness (0 by default) and layers' Metalness outputs vary it. At 1 the
path tracer takes the diffuse colour as the reflectance (F0) and drops the diffuse shading, so metals want bright
colours (copper ≈ `#c87850`); the specular level only applies to non-metals.
Albedo is stored **linear**; colours entered in the UI are sRGB and converted on upload.
**Masks** (FR8.23) are named; each texel holds a signed distance (px, < 0 inside; +1e4 = empty), the random of the
feature there and whether there is one. Every write makes a new version of its mask; `planMasks`
(`src/layers/masks.ts`) gives a version a **slot** texture only while a later layer reads it (as many slots as
versions alive at once), and the pipeline copies the written version from `mask out` into it. A layer reads its masks
as `maskIn()` (what it writes over, or Shape), `maskSrc()` (its source) and `limitAt()` (its limit; several masks are
combined by a small pass first). Bevel and Etch read a mask's distance directly where only shapes wrote it.

The **normal** map is derived in its own pass (Sobel over height × `heightDepth`, wrapping when tileable) into a
fourth texture whose `w` holds the world height in px (the path tracer marches it with hardware bilinear
filtering). It is never written by layers. Min/max height for the tracer's escape test come from a GPU 8×8
block reduction followed by a tiny readback.

All targets are RGBA32F (`EXT_color_buffer_float`); shaders address texels with `texelFetch` and do their own
wrap/clamp (`fetchT`, `sampleT`), so tiling never depends on sampler state.

## 6. Lighting (`project.lighting`)

```ts
Lighting {
  sky:     { enabled, zenith, horizon, intensity, image, rotation }, // gradient dome or an equirectangular image, sampled by escaping BSDF rays
  ambient: { color, intensity },                        // un-shadowed fill at the primary hit
  lights:  Light[]                                      // ≤ 8
}
Light = { id, name, enabled, type: 'directional' | 'point', color, intensity,
          // directional: azimuth°, elevation°, angularRadius° (soft shadows)
          // point:       x, y (0..1 user space), z (px above height 0), radius (px), range (px, 0 = inverse-square only)
          refDist?,  // point: px at which intensity 1 lights white to 1.0 (falloff (refDist / d)², default 64)
        }
```

A point light's `refDist` is not a slider: it is a px length that `scalePixels` scales with the light's z, radius and
range, so a resized canvas or a supersampled render keeps the light as bright (lights added later start at 64).

Point lights are draggable gizmos in the viewport; so are suns, on a sky map about the texture centre (angle = azimuth,
distance = elevation; FR3.1).

---

## 7. Path tracer (`src/render/pathtracer*.ts`)

A progressive, unidirectional path tracer in a single fragment shader, run once per sample into an RGBA32F
accumulation target (running mean). Specialised for a height field `z = h(x, y)` under an orthographic,
top-down camera:

- **Primary hit** is analytic: the pixel (plus sub-pixel jitter) at height `h`. No primary ray march needed.
- **Visibility** (shadow rays, bounce rays) ray-marches the height field in ~1 px xy steps, escaping once the
  ray is above the field's max height and rising, then bisects for a precise hit. Rays wrap on tileable projects;
  otherwise they leave the texture over an infinite plane at height 0 (`render.edgeMode`).
- **BRDF**: Lambert diffuse + GGX specular (Smith height-correlated, Schlick Fresnel, F0 = 0.08 × per-pixel specular level × `render.specular` scale, tinted
  toward the albedo's hue by `render.specularTint` — 1 by default, 0 for white glints),
  lobe chosen stochastically; GGX via visible-normal sampling.
- **Ambient occlusion** (optional): a horizon-based pass over the height field; surface lighting × AO^strength.
- **Next-event estimation** for directional (cone-sampled, soft) and point (sphere-sampled, soft) lights.
  Sky radiance arrives via BSDF-sampled rays that escape; emissive texels contribute when hit (bounces) and at
  the primary hit.
- **Bounces** `0..4` (indirect light), firefly clamp, deterministic RNG seeded by pixel and sample index so the
  optimiser can render reproducibly.
- **Output**: linear HDR radiance; alpha = albedo opacity.

---

## 8. Post-processing (`src/render/post/`)

A user-ordered stack of `PostFilter { id, type, enabled, params }`, each a pass (or several) over the float image:

| Filter   | Notes                                                                                                                                                                                  |
| -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Glow     | threshold + soft knee, multi-level down/up-sample bloom, intensity, radius, tint                                                                                                       |
| Blur     | separable Gaussian, radius px                                                                                                                                                          |
| Tonemap  | exposure (EV) + operator: clamp, Reinhard, ACES (fitted), AgX, Uncharted 2                                                                                                             |
| Grade    | brightness, contrast, saturation, hue shift                                                                                                                                            |
| Pixelate | block size (renders big, quantises down)                                                                                                                                               |
| Sharpen  | unsharp mask                                                                                                                                                                           |
| Palette  | nearest-colour in OKLab or RGB to a palette (Quake, Doom, PICO-8, EGA, CGA, Game Boy, C64, RGB332, custom hex list, auto/k-means from the image), with ordered (Bayer 2/4/8) dithering |

Before display/export the buffer is encoded to sRGB (with a clamp if no tonemap filter is present).

## 9. Reference matching (`src/match/`, `tools/harness.ts`)

- **Metrics** (pure TS, unit tested) compare a render to a target image, alignment-insensitive by default:
  colour distribution (sliced Wasserstein in OKLab), radial power spectrum of luminance (frequency content),
  gradient magnitude/orientation histograms (edge character), multi-scale local contrast; plus an aligned
  per-pixel term (OKLab L1 at several blur scales) for layout-sensitive targets like UI elements; structure at the
  best wrap shift (tileable textures); a GPU **texture** term — VGG-19 Gram statistics after matching colours
  (FR8.1), shift-invariant, which tells pattern families apart; and a **windows** term (FR8.19) — local patches of
  render and reference at up to 512 px matched both ways, so fine detail counts and the layout doesn't; and an opt-in
  **motifs** term (FR8.27) — the reference's rivets, bolts and studs held in place, for a start that can already make
  them.
- **Colour fitting** (FR8.2) solves colours directly before any search.
- **Optimiser** (in-app "Match" workspace and headless): an evolution strategy over the unlocked numeric/colour
  params of the stack, rendering each candidate deterministically at low sample counts; adaptive step sizes,
  restarts, and optional structural mutations (toggle/insert/remove layers).
- **Harness** (`npm run harness`): launches the app headless in Chromium via Playwright and exposes
  `render`, `compare` and `optimize` commands over project JSON files, writing PNGs and metric reports so Claude
  can iterate by eye and by number.

## 10. UI (Cinderforge)

The editor uses the _Blender-tempered_ Cinderforge editor language:

- **Ground** Void `#17191c`, Base `#1e2124`, Panel `#24282c`, Raised `#2c3136`, Sunken `#1a1d20`;
  **lines** Hairline `#363c41`, Line `#4a5259`, Line strong `#6b757d`, Sigil `#7ea9b0`, Pill `#9ed0d6`;
  **text** hi `#f1efe9`, body `#d7d6d0`, lo `#8f989e`; **ember** ramp with Ember 500 `#f66e10` as the one accent.
- IBM Plex Sans for tools, IBM Plex Mono for readouts, Cormorant Garamond caps for titles only.
- Blender density: 24 px rows, label left / value right, 3 px radius on fields and panel cards only, square
  buttons; collapsible panel cards with a disclosure chevron.
- One ember per screen: Halo for the active tool / focused field, Underlight bar for the active tab,
  the heat button for the single primary action (Export).
- Category hues (stroke only): Stone = shapes, Gold = lights/emissive, Teal = filters, Sky = patterns,
  Rose = textures/noise, Violet = post.

- Buttons are _Forged keys v2_ (`.fk`): a flat face on a 2px lip; one **lit** key per rail (workspace, channel view),
  **latched** toggles with a pilot lamp, one ember **primary** key (Export / Optimise), studs for row and panel icons.
- Field names carry tooltips (Tippy.js, theme `cinder`): the hint, what each option does, the key and default.

Layout: top bar (menus and Undo / Redo, the workspace rail centred, primary action: Export…, the Export dialog) · left a stack of the **Project**
panel (its name as the title, size, description: what every variant shares), the **Variants** panel (FR10) and the
**Outliner** (Project settings, one Layers list with Diffuse / Height columns headed by the Base row, and collapsible
groups, Lights headed by the Environment row, Post) · centre **Viewport** (channel rail, zoom/pan, tile preview, light gizmos, shape editor), or the
**Match**, **Tiling** (FR9: 3 × 3 before / fixed / hotspots, the fix search's settings, Keep this / Discard) or
**Variants** workspace (cards of every variant) · right **Properties** of the selection (Project settings: Canvas and Path
tracer; the Base row: the base material; Environment: lighting presets, sky light, ambient; ◆ marks what the shown
variant changes) · bottom status bar.
